# Manual window picker ownership and Stop

The existing manual window picker now freezes one `CaptureRequest` before dispatch. It keeps that request and any exact admitted/retained `CaptureSessionContext` separate from the global manual-active flag. The picker shows an active title only while the latest lifecycle snapshot matches the full session ID, request, generation, requested target and actual target for a selected window. PID, HWND, title, executable and class are all part of the window boundary. A Starting/null observation is pending, not accepted ownership. An unrelated manual or automatic capture cannot supply this picker's title or Stop authority.

The picker stays open after selection and displays its current status and a bound Stop button. Its singleton view model observes lifecycle snapshots for the host lifetime, re-reads the latest state when delivering a UI update, and unsubscribes on disposal; closing a popup does not reset ownership. Local request/command revisions prevent older async completions from replacing a newer selection. The view model also checks availability inside its command handlers, because a disabled button alone cannot prevent programmatic or stale command calls.

Stop from this picker supplies its exact context to `CaptureLifecycleCoordinator.StopOwnedManualAsync`. The coordinator checks identity under its existing serialized owner before the null-context reservation-release branch or any backend Stop call. A replacement session, changed window metadata, unrelated source, closed admission or null context rejects without affecting the current capture. The old global/manual Stop route remains for its existing callers. After exact Stop, the source manager may resume its existing automatic/configured capture behavior; that new capture is never attributed to the picker.

An exact failed Stop with retained context keeps a retry and displays a typed, fixed-text warning. Raw failure messages and codes can contain local paths or device identities, so the picker never places them in visible or accessibility status; the original typed failure remains unchanged for the existing diagnostics. Closed admission still shows any safe failure warning, including storage pressure, while keeping Stop unavailable. If cleanup released the context but media finalization failed, the picker shows a warning with no Stop authority; it does not call that clean success. A failed start that retained an unapproved actual target may be stopped for cleanup through that exact retained context, but the picker never labels the broader target as an approved active window. A failed replacement can leave the previously owned context available for exact cleanup. Idle/null, including successful source loss, gives no proof that a private manual reservation was released and cannot enable this picker's Stop.

This is managed source and fake-test evidence. The popup was compiled but not launched; no window/device/OBS capture, native release, pixel-boundary validation, final-package journey or media success was qualified. Production Pause/Resume/Split remain `Unsupported`. Offline/account-free behavior, manual priority, fail-closed source loss and original media preservation are unchanged.
