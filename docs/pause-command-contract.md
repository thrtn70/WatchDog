# Tutorial pause/resume command and acknowledgment contract

This is an unregistered, pure managed model for a future manual tutorial session. It does not dispatch `ObsKit.NET` calls, acquire outputs, change media, register a participant or make a pause control available. `CaptureLifecycleCoordinator.PauseAsync`, `ResumeAsync` and `SplitAsync` continue to return typed `Unsupported`. The existing lifecycle and ingestion owners retain all production authority.

## Required owned outputs

A command binds the exact manual `SessionRecording` request (including `StartupExpectation`), session ID, request ID, positive generation, complete actual window/display/region target and a caller-supplied common epoch. It requires a healthy, available, active snapshot of that same request. Replay, Both, automatic capture, wider or changed targets and unknown output capabilities reject before effects. The selected camera is required only when the request explicitly includes it and the current manifest admits that exact camera device. A saved camera preference does not create a participant.

The screen output owns screen video and every `AudioTrackPlan` encoder route: combined product track 1, or separate tracks 1 and 2. The independently retained camera output owns camera video and the internal compatibility audio at mixer 5, native output track 0. Mixer 5 is not product track 5. Each output has a distinct nonempty output epoch; rotating a segment changes the screen output epoch. Every required output capability declaration binds the full capture identity, and a camera declaration also binds the selected exact camera device ID. It must declare pause and resume support and exactly its required streams. A foreign capture's same-shaped declaration rejects before command creation. Reusing an output epoch with changed input-clock anchors or transform IDs rejects; an actual rotated output needs a new epoch. The model copies these declarations before returning a command. These declarations are supplied model capabilities, not native qualification.

Each anchor also requires an immutable `PauseMediaTimingDeclaration`: a nonempty `TimingId`, compatible `PauseDecodedUnitKind`, and positive rational `SecondsPerDecodedUnitNumerator/Denominator`. Screen/camera video requires `VideoFrame`; product/compatibility audio requires `AudioSample`, meaning a per-channel sample-time unit, not bytes or channel-multiplied samples. Admission takes one bounded indexed snapshot of caller anchors, validates it and retains that same snapshot. Unreadable storage rejects before effects. Both clock declarations and their exact stored scalar representations remain frozen under retained output identity; even an equivalent fraction cannot replace one. A timing ID is a scoped correlation token, not native authority. There is no default from the input clock, configured FPS, neighboring PTS or packet arithmetic.

Only Running may plan Pause and only a previously committed Paused state may plan Resume. Operation ID must be nonempty and differ from the preceding operation; sequence increases by one. Resume requires the same participant epochs and anchors as the committed pause. The future caller must retain the newest immutable state and serialize planning, dispatch and reduction through the existing lifecycle owner. It must not replay an older state as new authority.

## Effects and terminal arbitration

The owner must distinguish **before any dispatch could cause an effect** from **after any dispatch could cause an effect**. A cancel, stop, exact source or device loss, or shutdown before dispatch rejects with the unchanged modeled state. Once dispatch may have begun, any such intent, missing/duplicate/foreign/unknown/rejected acknowledgment, mismatched epoch or track packet, or uncertain partial result makes the operation terminal. It requests stop and finalization for every currently owned and commanded output epoch. It never automatically resumes a successfully paused subset. A late success cannot clear terminality. Production source/device-loss and shutdown handling must continue independently; this model cannot suppress them.

A command from another capture identity cannot mutate the supplied current state or authorize release of its outputs. It is rejected against that state; the original capture owner remains responsible for reconciling any effects under its own exact identity. A stale command within the same identity that could have been dispatched retains both current and commanded output epochs as cleanup obligations. If an already-terminal state later learns of another possibly dispatched epoch, terminality remains latched and all known epochs require fresh cleanup evidence bound to that latest reconciliation.

One acknowledgment per output must match the command's operation, sequence, full capture identity, action and output epoch, and report an applied effect. It contains one `PauseStreamEffect` per declared stream, with the frozen transform ID and input boundary index. Pause identifies the first excluded input; resume identifies the first admitted input. Input units are video frames or audio samples, never encoded packet PTS.

The approved option B separates capture effects from raw media evidence. `PauseInputClock` declares an input index at an exact rational capture origin, a positive rational number of seconds per input unit and a nonempty transform ID. Capture seconds equal `originNumerator/originDenominator + (inputIndex-inputIndexAtOrigin)*secondsPerInputNumerator/secondsPerInputDenominator`. The reducer combines the fractions with `BigInteger` and requires an exact, representable `TimeSpan` tick value equal across every stream/output and strictly greater than the preceding capture boundary. Invalid denominators, wrong transforms, unequal or fractional ticks reject. No tolerance, rounding, public rational-time replacement or resume re-anchoring is introduced. Equal IDs and supplied clock facts do not prove actual native alignment.

This permits a modeled pause at capture 1.6 seconds and resume at capture 3.2 seconds while media timestamps remain continuous at the 1.6-second cut. Raw media PTS never supplies capture-clock authority. Codec packet boundaries need not coincide with the cut; incompatible **input** grids still reject.

After complete fake acknowledgments, the reducer returns only `ModeledCommitted`, a new pure state and a requirement to suspend progress expectations after aggregate Pause or re-arm them after aggregate Resume. Source/device-loss checks and stop/shutdown arbitration must continue while intentionally paused. It does not register or suppress production liveness; `NativePauseProven`, `NativeAlignmentProven` and `NativeLivenessAdmitted` are fixed false. Existing persisted `SessionMediaSegment` offsets remain estimates and are not rewritten as native timestamps.

Terminal cleanup remains pending until every exact participant/output epoch has an operation-bound receipt that accounts for native resource release and media finalization. If finalization failed, explicit original preservation yields a terminal warning, never successful media. A stopped flag, idle snapshot or return from a command does not prove release. Missing, duplicate, stale or foreign receipts cannot complete modeled cleanup. Actual ordered stop, output disposal, media preservation and ingestion drain remain future existing-owner work; this pure receipt cannot prove any of them occurred.

## Unregistered managed participant copy and drain model

`PauseParticipantOwner` owns one pristine initial state and the newest immutable state thereafter. Both states and commands retain the full frozen context, including startup expectation and exact requested/actual targets; matching numeric IDs cannot substitute for that context. The enriched admitted-device manifest is not compared by object identity. The owner rejects advanced-state import and commands planned against an earlier state. It atomically reserves all participant registrations, with a default limit of 64 and a hard configurable range of 1–1,024. Registrations are retained without eviction and get positive owner-issued generations. Duplicate operations and exhausted capacity reject without minting partial registrations.

Each opaque registration has one effect callback gate. Admission requires the identical registration object, and active leases are bounded by the declared stream count. An entered callback synchronously copies one complete aggregate acknowledgment into privately owned immutable input-effect records using bounded indexed reads. Caller collections/readers are not retained. Malformed, duplicate or over-capacity evidence latches invalidity. Closing rejects new entries immediately, allows entered callbacks to finish copying, and drains only after their idempotent lease disposal. Canceling one waiter does not reopen admission or cancel the shared drain. These are managed supplied-evidence callbacks, not native callback lifetime or call-bound proof.

The evidence adapter commits through the existing acknowledgment reducer only after all gates close and drain. Dispatch-start and terminal intent are sticky; a post-dispatch stop, cancellation or source/device loss becomes terminal immediately even while callbacks remain entered. A late acknowledgment never revives recording. Repeated reductions preserve the same resulting state while it remains current, but new terminal intent overrides an earlier modeled success and late dispatched epochs expand cleanup obligations.

Before exposing a terminal result, the owner includes every retained operation already known to have possibly dispatched, including those whose callbacks are still entered. Cleanup tickets refer to every retained issued gate for the exact obligated output epoch. A newly created gate cannot stand in for drainage. Drainage alone supplies no resource-release or finalization evidence: a caller must separately provide an exact full-context, operation-bound release receipt after the ticket drains. Exact duplicates are idempotent; conflicting accepted evidence prevents completion. A changed terminal state invalidates all earlier tickets and receipts and requires fresh evidence for every known epoch. Repeated reduction of the identical terminal state preserves its cleanup revision. The adapters remain unregistered and connect only fake evidence to the pure reducers; no production callback, output pause, liveness or UI wiring is added.

## Deferred boundary-adjacent media custody

Every existing registration reserves one separate media slot at operation creation. Effect commitment does not wait for encoded media that may only appear after resume. `TryAcceptMediaCoverage` accepts one output receipt under the identical retained registration, full context, operation/sequence/action/output epoch and registration generation. It is accepted only after that operation's modeled effects committed. Late coverage updates only its original slot; it does not replay an older effect reducer or change Paused/Running state.

The receipt contains exactly the declared streams. Each has one to eight packet witnesses, each with one to eight capture-support spans. These are explicit model capacities, not native codec promises. Packet facts include an opaque positive lifetime-scoped identity, required `MediaTimingId` matching the retained stream declaration, raw PTS and rational duration/timebase, decoded input units, leading/trailing trim and ordered disjoint half-open input spans. Raw PTS may be negative and is not mapped to capture time. The field `DecodedInputUnits` counts decoded presentation units; its name does not prove accepted-input lineage.

The managed choice D revision requires `Duration * PacketTimebase = DecodedInputUnits * MediaUnitPeriod` using exact `BigInteger` products against the retained declaration. Media-unit timing is independent of the capture-input clock. Retained support counts still equal decoded units minus leading/trailing trim. No rounding, normalization, tolerance, inference or legacy-shape fallback is used. Effect acknowledgments remain capture-only; the exact common later integral 100ns cut and all current identity, bounds, callback and terminal rules are unchanged. Separate media timing cannot create a reachable intersection between incompatible or sparse capture grids.

These equations validate consistency of supplied model facts only. For ordered support spans `[a_j,b_j)`, the claimed mapping is decoded offset `LeadingTrim + sum(previous span lengths) + k` to accepted encoder-input index `a_j+k`. A native producer must independently prove that one-to-one presentation lineage through transforms, successful codec acceptance, reorder/delay and emission. Audio coordinates are after the applicable mixing/resampling conversion presented to the encoder. Authoritative edge trims cannot hide omitted or paused input or invent support; variable-unit or non-one-to-one representations are outside this candidate. Unsupported representations fail closed. The receipt proves neither authentic timing/trim nor complete final-file coverage.

Pause coverage must reach the first excluded input; resume coverage must start at the first admitted input. Support cannot include any known paused input interval or overlap another distinct packet. Repeated references to the same packet across boundary receipts must be identical, including `MediaTimingId` and the exact duration/timebase representation. Whole-packet facts must be complete before first publication; an accepted witness cannot later grow. A crossing packet may include separate pre-pause/post-resume spans after both effects are known. Unknown dispatched effects cannot justify successful coverage. A future pause cannot retroactively exclude already accounted retained input.

Boundary-adjacent receipts do not account for every packet or retained input in a recording. Successful native finalization separately requires complete actual-file support without omitted or duplicate presentation, canonical-to-output correspondence, codec trim/drain and helper/container completion. Failed media finalization can still end in safe cleanup when exact identity, drained/accounted failure, independent resource release and original preservation satisfy the existing release contract. Valid delayed evidence may fulfill its original still-accepting slot; lateness alone does not imply failure or permit revival.

The owner reserves a copy slot under its lock, reads bounded caller collections outside it, then publishes immutable scalar copies under the lock. Throwing or conflicting evidence is sticky failure. Exact repeated coverage is idempotent. Media slots survive effect-gate closure and are never evicted to admit more operations. Foreign registration/context cannot mutate another owner's ledger. An entered media copy remains custody until it returns even if terminal cleanup or failure accounting occurs meanwhile.

`AccountMediaCoverageFailure` supplies the explicit failed completion point; it introduces no clock or timer. Missing, malformed, conflicting or unrepresentable evidence forces sticky `MediaEvidenceLost` terminal reconciliation across all possibly dispatched epochs. Successful late coverage never revives recording. Pre-dispatch pause rejection still does not consume the capture owner's independent Stop/source-loss/shutdown responsibility.

Cleanup requires effect drainage, no entered media copies, accounting for every dispatched registration's media slot, and the existing exact release/finalization receipts. Merely closing an effect gate does not complete a media slot. Explicit failed media accounting permits only failed finalization with original preservation, yielding a warning. It never becomes successful media. New failure or newly disclosed dispatch invalidates earlier cleanup tickets so releases must be reconciled again. No native resource release, file preservation or media success is inferred from these model facts.
